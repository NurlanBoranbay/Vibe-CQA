# Vibe CQA — Conversation Quality Analytics

**VibeTeam · хакатон Freedom Broker (CQA), ноябрь 2026**

Оценка работы оператора в чатах и звонках (RU / KZ / EN) по настраиваемому чек-листу: по каждому критерию — ответ,
баллы, вес, объяснение и ссылка на реплику (у звонка — на момент записи). N/A перераспределяет вес, грубая ошибка
отмечается отдельно. Оценку можно оспорить; проверяющий подтверждает или меняет её, итог пересчитывается, исходная
оценка сохраняется.

## Запуск

```bash
docker compose up -d --build
```

Откройте **http://localhost:8030/ui/**. Система стартует с демо-данными (`data/seed/demo.sqlite`): оценены все
65 диалогов DEV и 10 контрольных чатов FBroker (прогоны №1 и №2), есть примеры апелляций (решённая и ожидающая),
второй чек-лист и набор Swap без оценки. Ключи и модель для просмотра не нужны. Роль (Оператор / Проверяющий / Методолог / Админ) переключается кнопкой в правом верхнем углу.

Для новых оценок нужна модель: «Модели и ключи» (роль Админ) → OpenRouter → вставить ключ → добавить модель и сделать
её моделью по умолчанию. Свой сервер vLLM задаётся через `GEMMA_BASE_URL`. Остальные настройки — в
[.env.example](.env.example).

Без Docker: `pip install -r requirements.txt && python -m cqa.seed && python -m uvicorn cqa.api:app --port 8030`

## Модель и стоимость

**Gemma 4 26B-A4B** (thinking) на своём сервере vLLM. Одна оценка = 3 прохода с голосованием (+ повторный запрос
только по критериям, не прошедшим проверку).

- **$0** за оценку на своём сервере;
- **≈ $0.003** за оценку по тарифу OpenRouter — весь DEV (65 диалогов) стоит $0.19.

## Точность

Gemma 4 26B-A4B, 3 прохода с голосованием. Эталон — 20 диалогов с ручной разметкой ([bench/](bench/)): `dev` и
`hold-out` (написан отдельно, с ловушками: приветствие бота вместо оператора, неверный срок T+3, ошибка в арифметике,
просьба назвать SMS-код). Совпадение — доля из 80 ответов по критериям в каждом наборе.

| Промпт | dev | hold-out | грубые ошибки найдены | ложные грубые | ошибка итога (MAE) |
|---|---|---|---|---|---|
| «Строгий» | **98.8%** | **98.8%** | 100% | 0 | 2.9 / 3.3 |
| «По смыслу» | 97.5% | 97.5% | 100% | 0 | 5.2 / 3.0 |

На 65 диалогах DEV организаторов (эталона нет) система находит все 8 грубых нарушений, проверенных вручную, и ни
одного лишнего.

## Контрольный набор

1. «Диалоги» → «Загрузить диалоги» → `group_id` от организаторов.
2. «Новые» → выбрать все → «Оценить».
3. «Оценки» → «Экспорт results.json» → `results/prod/results.json` (ровно 10 записей) → commit, push.

Или одной командой: `python -m cqa.cli --source "<ссылка>&group_id=<id>" --export results/prod/results.json`

## Как устроено

- **Модель не считает баллы.** Она выбирает ответ и номера реплик; вес, N/A и округление считает код
  ([scoring.py](cqa/scoring.py)) по правилам чек-листа.
- **Проверка ответа кодом** ([validate.py](cqa/validate.py)): допустимые значения, N/A только где разрешено, реплики
  существуют, «Да» не может опираться только на реплики бота или клиента. Ошибки → повторный запрос → «нужна проверка».
- **Чек-лист — это данные.** Новый или изменённый критерий применяется без правки кода; каждое сохранение — новая
  версия. Системный промпт выбирается у чек-листа: «Строгий» или «По смыслу» (для официального).
- **Звонки:** ошибки распознавания речи и неполная запись не считаются ошибкой оператора.
- **История:** каждая оценка хранит модель, промпт и версию чек-листа; повторная оценка не затирает прежнюю.

**Стек:** FastAPI + SQLite, интерфейс — HTML/CSS/JS без сборки ([web/](web/)), который можно встроить в Dynamics 365
как HTML-ресурс (`window.CQA_CONFIG = {apiBase: "…"}`).

```
cqa/         сервер: API, оценка, промпты, проверка, подсчёт, экспорт
web/         интерфейс
checklists/  официальный чек-лист
data/        набор DEV и готовые оценки для первого запуска
results/     results.json для сдачи
bench/       эталонные наборы и замер точности
```
